# 架构决策记录（ADR）

本文件记录设计里的取舍。每条包含：**状态**（已实现 / 仅接口 / 待实现）、**背景**、**决定**、**代价**。

只看结论的读者可以跳到文末「已知局限」。

---

## ADR-001 判断职责拆成三个角色，而非一个

**状态**：接口已实现，判定逻辑待补

**背景**：一次写作需要同时校验三类东西——世界观是否自洽、人物行为是否合乎人设、情节走向是否在预期区间。若合并为一次判断，单次推理要同时权衡三类标准，且失败时无法定位问题类别。

**决定**：拆成三个独立角色，各自只持有一类判断标准，各自持有独立的数据库。

**理由**：
- 判断维度解耦。每个角色不必在一次推理里权衡互不相关的标准。
- 可定位性。判定失败时可直接得知是设定、人设还是走向出了问题，修订有明确方向。

**代价**：跨类冲突无人负责。设定与人设各自合规、组合起来不合理的错误，三个角色会全部放行。这是本结构的已知盲区，缓解方案见文末。

## ADR-002 写作角色不持有数据库读写权限

**状态**：已实现

**背景**：写作角色是唯一产出正文的角色，也是最容易为了"让本章成立"而修改前提的角色。

**决定**：写作角色不持有任何数据库的写权限，也不持有读连接；它只能通过白名单工具读取快照。

**实现**：`src/novel_mas/tools/registry.py` 的角色白名单。越权调用直接抛 `PermissionError`，不是约定、不是注释。

**理由**：把"隔离"从规范变成运行时约束。规范会被绕过，异常不会。

**代价**：写作角色无法自建所需数据，必须依赖其他角色提前准备；编排层要多一步取数。

## ADR-003 小事件链接只产出候选，不直接入库

**状态**：已实现

**背景**：写作过程中会自然产生细节（某人提到一件往事、某处埋一个物件）。这些细节可能成为后文的伏笔。

**决定**：写作角色可以提出"事件 A 与事件 B 相关"的候选，但入库权归世界意志，且入库前需通过查环与依据校验。

**理由**：若写作角色可自行入库，它会为自己临时编造的伏笔补一条"回收"记录，把行文漏洞焊成"结构完整"。这类自补在事后极难识别。

**代价**：多一次审核往返，写作链路的延迟增加。

## ADR-004 大事件必须携带约束，小事件不强制

**状态**：已实现（校验）；存储已实现

**背景**：事件分大小。判据不是篇幅，而是**是否锁死了后续可能性**——某城被毁、某人死亡会关闭大量叙事路径，某人在巷口捡到一枚铜钱不会。

**决定**：大事件入库必须携带 `constraints`，描述它关闭了哪些可能性；缺失则拒绝入库。小事件只做留痕。

**理由**：只记录"发生了什么"、不记录"因此不能再做什么"，后文必然出现前后矛盾。

**代价**：大事件的结构化成本高，需要人工或模型额外提炼约束。

## ADR-005 走向曲线校验单章最大落差

**状态**：已实现

**背景**：走向曲线以章节为单位给出目标情绪值。高值对应温暖、重逢、日常；低值对应分离、死亡、堕落。期望值可自由设定，但**单位章节内的变化速度**有叙事上的上限。

**决定**：`validate_curve` 校验相邻章节落差，超过阈值（默认 25）给出警告。

**理由**：单章从高位跌到低位属于情绪断裂，读者体验为"硬转"。连载场景下这类断裂往往难以补救。

**实现选择**：返回警告列表而非直接拒绝。曲线规划阶段允许越界，但要求用户知情。

**代价**：阈值是经验值，不同题材容忍度不同，需要按项目调参。

## ADR-006 走向分与文本质量分分开计

**状态**：部分实现（走向分用词频估计，质量分未实现）

**背景**："这篇写得好不好"与"这章把故事带向哪里"是两个正交维度。文笔极佳但主角死亡的章节，质量分高、走向分低。

**决定**：走向分只衡量情绪方向与目标值的接近程度，不承担质量评价。

**理由**：两者混计会产生错误的学习信号——写作角色会认为"写得好看"等同于"方向正确"，从而持续偏航而不自知。

**代价**：需要两套独立的评估机制，评估成本上升。

## ADR-007 模型调用抽象为可替换接口

**状态**：已实现

**背景**：整条链路需要能在不联网、不产生费用、结果可复现的条件下验证。

**决定**：模型调用抽象为 `Provider` 协议（`complete()` + `tokens_used`），内置确定性的 `FakeProvider`。

**理由**：
- 链路验证与模型质量解耦。结构错误和模型能力不足可以被分开定位。
- 接入真实模型时只替换 Provider，编排逻辑不改动。

**代价**：假模型产出的正文是占位文本，不能用于评估写作质量；打分同样是占位实现。

## 已知局限

1. **跨类冲突无检测**。见 ADR-001。候选方案：增设一个只读各角色裁决结论、不读原始数据的仲裁角色；或要求各角色在裁决时一并上报"最不确定的地方"，由编排层检测重叠。两者均未实现。
2. **重跑不幂等**。`chapter_scores` 等表使用普通 INSERT，同一章重复运行会产生重复记录。对照实验前必须先修。
3. **无端到端测试**。当前仅有冒烟测试（建库、注册、权限、纯逻辑），没有"输入一部作品 → 输出一章"的链路测试。
4. **评估指标未定**。缺少 MAS 与单智能体对照实验的指标体系与协议。
