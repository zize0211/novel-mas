# 踩坑记录

测试和联调时踩到的坑，按「现象 → 怎么确认 → 根因 → 修法/以后怎么做」记。

两个用途：
1. 下次遇到同样的现象，先查这里，别重新猜一遍；
2. 面试时它比 README 更能说明「这个人真的跑过东西」。

分三类：
- **A. 代码缺陷**：已改代码，附提交号
- **B. 测试方法**：代码没错，是我的验证做法有问题
- **C. 自检写法**：测试本身写错了

## A. 代码缺陷（已修）

### A1. 启动器误杀服务：Edge 复用了旧实例

**现象**：双击 `start-app.bat`，窗口开了，一两秒后所有按钮 `Failed to fetch`。

**怎么确认**：看 `app.log`——

```
14:46:25  起了服务，pid=70688
14:46:27  服务就绪
14:46:27  开了窗口，browser pid=72856
14:46:27  窗口关了            ← 1 秒
14:46:27  已停服务 pid=70688
```

**根因**：同一个 `--user-data-dir` 已有 Edge 实例在跑时，新启动的进程会**立刻退出**（把 URL 交给已有实例）。启动器用 `Wait-Process -Id $browser.Id` 等它，于是立刻返回，判定「窗口关了」，把刚起的服务杀掉。旧实例其实是前一天 23:16 留下的。

**修法**（`f4238af`）：不看单个句柄，改成「等这个 profile 下的浏览器进程全部消失」：

```powershell
function Get-ProfileProcs {
    Get-CimInstance Win32_Process | Where-Object {
        $_.Name -match '^(msedge|chrome)\.exe$' -and $_.CommandLine -like "*$profileDir*"
    }
}
while ((Get-Date) -lt $deadline) {
    Start-Sleep -Seconds 2
    if (@(Get-ProfileProcs).Count -eq 0) { break }
}
```

### A2. `.env` 里的 key 被进程环境变量压住 → 401

**现象**：

```
RuntimeError: 模型返回 HTTP 401：{"error":{"message":"Authentication Fails,
Your api key: ****hDQM is invalid"}}
```

`.env` 里明明是另一把 key（尾号 6203）。

**怎么确认**：比三处尾号——`.env` 文件、`os.environ`、`GET /api/config` 返回值。三者不一致就是它。

**根因**：`_load_dotenv()` 用 `os.environ.setdefault`，环境变量已经存在的键不会被 `.env` 覆盖。进程是从别的工具继承了 `DEEPSEEK_API_KEY`（尾号 hDQM），于是：
- 实际用的 key 是环境里那把（无效）
- GUI 面板显示的也是它
- 在面板里改 `.env` 根本不生效

**修法**（`785afa1`）：**`.env` 优先，环境变量兜底**。注意不能按名字逐个混着查——否则 `.env` 写的是 `DEEPSEEK_API_KEY`、环境里恰好有 `OPENAI_API_KEY`，仍会先命中最先出现的那把无关 key。正确写法是「先把所有候选名都在文件里找一遍，再找环境变量」。

### A3. 瞬时 DNS 失败把整章废掉

**现象**：

```
连不上模型 https://api.deepseek.com/v1：[Errno 11001] getaddrinfo failed
```

**怎么确认**：同一台机器上立刻再试一次就通了；`Resolve-DnsName api.deepseek.com -Type A` 有结果。说明是瞬时抖动（休眠唤醒、Wi-Fi 切换后 DNS 缓存失效）。

**修法**（`ad52399`）：网络类错误自动重试一次（等 1.5 秒）；解析失败时在错误里加一句人话，告诉用户「等两秒再点」。

### A4. 自检里的删除范围写宽了，误删用户手写的条目

**现象**：自检断言失败，返回的库里只剩一条：

```
[{'title': '条目1', 'body': '丁'}]   ← 期望是两条（含手写的「雨」）
```

**根因**：重灌世界观时我写的清场语句是「删掉这本书所有 `source='user_inject'` 的条目」，把用户**自己起标题**写的那一条也删了。

**修法**（`88d8c8c`）：范围收紧成「标题像 `条目N` 的」——

```sql
DELETE FROM world_bible
 WHERE book_id = ? AND source = 'user_inject' AND title LIKE '条目%'
```

这条要记住：**删除语句的范围，永远是先问「有没有别的东西也符合这个条件」**。

## A2'. 脚本编码：编辑工具会把 BOM 吃掉

**现象**：改完 `start-app.ps1` 双击没反应；命令行跑报语法错：

```
字符串缺少终止符: '。
语句块或类型定义中缺少右“}”。
```

**怎么确认**：看文件头三个字节。原来是 `EF BB BF`（UTF-8 BOM），被编辑工具写成纯 UTF-8 后就没了。

**根因**：Windows PowerShell 5.1 对**无 BOM 的 UTF-8** 按 GBK 解，中文注释里的全角引号会被当引号吃进字符串。

**修法**：文件头写了警告，改完 `.ps1` 要确认 BOM 还在：

```powershell
$b = [System.IO.File]::ReadAllBytes($p)
"{0:X2}{1:X2}{2:X2}" -f $b[0], $b[1], $b[2]   # 必须是 EFBBBF
```

## B. 测试方法上的坑（代码没错，是我的做法错）

### B1. 端口被旧进程占着，新服务根本没起来

**现象**：改了代码、重启测试服务、请求返回的还是旧行为（新接口 404）。以为改动没生效。

**怎么确认**：

```powershell
netstat -ano | Select-String ':8787' | Select-String 'LISTENING'    # 谁占着
Get-CimInstance Win32_Process -Filter "ProcessId=<PID>" | Select-Object CreationDate
```

`CreationDate` 比你的改动时间早，就说明打的是旧进程。

**后果**（这次的真实代价）：我起了三四个「测试服务」，其实全都因端口占用立刻退出，所有请求都打在你双击启动的那个旧进程上；最后排查时把那个进程杀了，你的窗口就断了。

**以后怎么做**：起服务前先确认端口空闲；起完核对 `pid` 与 `netstat` 报的一致。**更重要的：不要去动别人起着的服务。**

### B2. PowerShell 发中文 JSON，看起来像编码 bug

**现象**：用 `Invoke-RestMethod` 发 `{"style":"冷峻"}`，写进文件变成 `??`。

**根因**：PowerShell 把 body 按非 UTF-8 编码发出，服务端收到的就是坏字节——**客户端的问题**。

**以后怎么做**：中文参数的接口测试一律用 Python `urllib`：

```python
data = json.dumps(body, ensure_ascii=False).encode("utf-8")
req = urllib.request.Request(url, data=data,
        headers={"Content-Type": "application/json; charset=utf-8"})
```

另外：`Get-Content` 打印中文出现乱码，也不代表文件坏了——用 `read` 工具或 Python 读一遍再判断。

### B3. 看 commit 的汇总行会高估改动量

**现象**：`git commit` 报 `879 insertions(+), 560 deletions(-)`，但实际只改了几十行。

**根因**：LF/CRLF 归一化让整文件看起来全变了。

**以后怎么做**：核对改动量看 `git diff HEAD~1 --numstat`，那是真实行数。

## C. 自检写法

### C1. 自检不密闭：失败一次就把数据留在库里

**现象**：新加的断言第一次因为 bug 失败；修完之后再跑，报 `version: 4`（期望 2）——上一次残留的数据把计数顶上去了。

**根因**：断言依赖「库里原本是干净的」这个前提，但自检跑在真实库上（`data/*.db`）。

**修法**：每段自检开头先清场，结尾再清一次；不依赖上次跑的残留：

```python
conn.execute("DELETE FROM world_bible WHERE book_id = ?", (book,))
```

### C2. 断言的错误信息要能直接定位

写成 `assert x == y, x` 而不是裸 `assert x == y`——失败时打印的是实际值，不是一句 "assertion failed"。上面的 A4 就是靠打印出来的 `[{'title': '条目1', 'body': '丁'}]` 一眼看出「雨」被删了。

## 一条经验

**「报错原文 + 一个能立刻验证的判据」比任何猜测都值钱。**

今天最花时间的不是改代码，是分不清「代码没生效」和「服务没起来」——两者的现象都是「行为没变」。后来靠 `netstat` + `CreationDate` 一分钟定位。所以记录里每一条都写了「怎么确认」，而不只是「根因」。
